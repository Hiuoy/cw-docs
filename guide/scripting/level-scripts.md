# A map's level scripts

> Every custom map has its own level script, compiled by the build. This page says what it does and how to change it. **Status:** Done (2026-09-26).

## The three scripts of a map

The build compiles them with ACTS and puts them in `<game>\cw-mod\maps\<id>\scripts\`. The mod serves them only while that map runs.

| Script | Where it comes from | What it is |
|---|---|---|
| The level script, server side | `mapkit\level\zm_silver\zm_silver.gsc` in the repository | Starts Zombies on your map |
| The level script, client side | `mapkit\level\zm_silver\zm_silver.csc` | Registers the client half of what the server registers |
| The zones script | **Generated** from your map by every build | Your zones, how doors connect them, and your map's settings |

A readable copy of the generated zones script is kept in `<game>\cw-mod\maps\<id>\generated\`.

## What the level script does

| It keeps from Die Maschine's | It drops |
|---|---|
| The setup of the shared assets: effects, the weapon table, the announcer | The intro cinematic |
| The Zombies start: the loader, the minimap, the zone manager | The main quest, the Pack-a-Punch quest, the wonder-weapon quest |
| Perks powered from the start, unless your map has a power switch | Voice lines, music, dog rounds, intel, the side quest |

It prints one line when it runs, which also lands in the log:

```text
mapkit: level script running, start zone start_zone, 4 zones
```

## What the zones script looks like

This is the script of a map with four zones and three doors, as the build wrote it:

```c
#namespace mapkit_zones;

// The zones active when the match starts (MkZone active_at_start).
function start_zones()
{
    return array( "start_zone" );
}

// Every zone, then the connections.
function init()
{
    level flag::init( "always_on" );
    level flag::set( "always_on" );
    zm_zonemgr::zone_init( "start_zone" );   // active at start
    zm_zonemgr::zone_init( "machines" );
    zm_zonemgr::zone_init( "gallery" );
    zm_zonemgr::zone_init( "yard" );
    zm_zonemgr::add_adjacent_zone( "start_zone", "machines", "mapkit_door_0", 0 );
    zm_zonemgr::add_adjacent_zone( "start_zone", "gallery", "mapkit_door_1", 0 );
    zm_zonemgr::add_adjacent_zone( "machines", "yard", "mapkit_door_2", 0 );
}
```

Each door gets a flag, `mapkit_door_<n>`. Buying the door sets the flag, and the zone manager then treats the two zones as connected.

Its third function, `settings()`, holds what your objects set for the whole level: the exfil's hold time and attack area, the crafting items you turned off, whether perks wait for power, and which props are not solid. The level script calls it before the game's loader runs.

Do not edit the generated file: the next build writes it again. Change the map instead.

## Changing the level script

1. Copy the folder `mapkit\level\zm_silver` to a place of your own.
2. Edit `zm_silver.gsc`, and `zm_silver.csc` if you add something that has a client half.
3. Build with your folder:

   ```powershell
   cwlink build zm_silver <map>.mkmap --trace <trace> --level <your folder>
   ```

For a quick test with Die Maschine's own scripts instead of the map's, build with `--no-level-scripts`.

## Level script or inject script?

| You want | Use |
|---|---|
| Logic for this map only: a trap, a custom round rule, an effect at a place | The level script |
| Something for every map: a trainer, a debug tool | An inject script in `cw-mod\scripts`. See [Game scripts](/guide/scripting/gsc.md). |

## The rule that bites: both sides must match

The server script and the client script must end up registering the **same clientfields**, counted over everything they include. If the server side includes a system whose client half the client side does not include, every player is dropped with "Clientfield Mismatch" once the map has loaded. The shipped pair is balanced. When you add an include to one side, add its other half to the other side.

The mod logs the difference (`Clientfield diff`) and writes both lists to `cw-mod\clientfields_server.txt` and `clientfields_client.txt`.

## If it goes wrong

| What you see | Cause and fix |
|---|---|
| The build stops at the script step | ACTS is not on your PATH, or your script has an error. The build prints ACTS's message. |
| No `mapkit: level script running` line in the log | The map's scripts were not used: the map was not picked, or the build wrote no scripts. |
| "Clientfield Mismatch" | See the rule above. |
| Zombies never spawn | The zones script names no start zone: no `MkZone` has `active_at_start`. |
